## Pitfalls & conventions
- pnpm needs the private registry token from ~/.zshrc → wrap with `zsh -ic`, and `cd` into the repo first (zsh -ic starts at kit cwd).
- API clients are generated: `pnpm openapi:generate` from `data/api-schema/*.json` into `open-api/` — new backend endpoints need schema update + regeneration; don't hand-edit `open-api/`.
- Onboarding 2026-09-07: repo was on branch `feat/monitoring-plugin-update` (not main).
- **Tailwind preset scales are NOT default Tailwind (CTOOL-634 round-4 lesson, 2026-09-08)**: `@visable-dev/wlw-tailwindcss-config` redefines `theme.spacing` as `--v-size-N` = **N × 8px** (spacing-1=8px, 2=16, 3=24, 4=32, 6=48...). Writing `mt-4` "expecting 16px" yields 32px — every default-Tailwind mental-model spacing value renders 2×. Convert: px/8 = class number (24px → 3, 16px → 2, 32px → 4, 20px → 2.5, 12px → 1.5, 8px → 1, 4px → 0.5). Non-multiple-of-8 px → arbitrary `[Npx]`.
- **fontSize scale is emptied** in the preset (`fontSize: {}`) so `text-sm`/`text-base`/`text-xs`/`text-2xl` etc. are DEAD classes (only arbitrary `text-[14px]` works). Font utilities are the preset's custom `font-copy-100..600` / `font-display-300..1000` (e.g. 16px→`font-copy-400`, 14px→`font-copy-300`, 20/600→`font-display-500`, 16/600→`font-display-400`). `text-copy-*` (used in older repo code) is NOT a utility — it does nothing.
- **borderRadius scale only defines none/xs/sm/md/lg/full/DEFAULT** → `rounded-lg` = `--v-radius-l` = **12px**, `rounded-md` = 8px; `rounded-xl`/`rounded-2xl`/`rounded-3xl` don't exist — use arbitrary `rounded-[24px]`.
- Build/dev pipeline regenerates `public/product-editor-frontend/favicons/` with content differing from the committed files → favicon churn appears in `git status` after every build/validate. Always `git restore -- public/product-editor-frontend/favicons/` before staging.
- Tests mock `$t` to return i18n KEYS (params ignored) — assert keys, not translated strings.
- i18n: only `en.json` carries feature keys; other 21 locales fall back (verified de.json lacks them).


## CTOOL-679 round (2026-09-12)
- BFF server-route pattern for a new upstream API = copy CTOOL-637 commit 2a264d4a wholesale: `server/middleware/<name>-api.ts` (path match → X-Platform/cookie/forwarded-profile headers onto event.context) + `server/utils/<name>.ts` (`forwardXRequest(event, path, {method, body})` re-throwing via createError) + `server/routes/<name>-api/*.get|post.ts` (upstream path in a comment) + runtime config keys `<name>ApiUrl` / `dev<Name>UserProfile` in nuxt.config.ts. App-side util takes a fetcher param (no $fetch at import time — jsdom tests lack the global; resolve via `(globalThis as any).$fetch`).
- Consuming un-published visable-vue components locally: pnpm.overrides `link:` churns pnpm-lock.yaml (must be reverted); the CLEAN dev-link is a manual symlink — `rm -rf node_modules/@visable-dev/vue && ln -s ../../../visable-vue node_modules/@visable-dev/vue` (CTOOL-634 routing-lib precedent; re-create after any pnpm install). lib component dirs MUST contain their own `index.js` re-export or every downstream suite fails resolving `./components/<Name>` from the lib root index.
- GA4 `EventSpecificPayloadGA4` (app/types/tracking.ts) rejects extra props — no ad-hoc dimensions (company_id/banner_state) in click()/show() payloads; event_label + event_position only. TrackingGA4 exposes click()/show()/select()/trackEvent(), not a generic navigate().
- `nuxi typecheck` prints a scary volar stack trace "[Vue] Failed to create plugin TypeError: plugin is not a function" — baseline noise on clean main too; judge by `grep -c "error TS"` (must be 0) + exit code.
- (CTOOL-679 verification round) Two real SSR bugs the jsdom composable tests missed: (1) fire-and-forget `refresh()` loses the SSR race — banner never rendered server-side; wrap the initial fetch in `useAsyncData` so SSR awaits it. (2) `globalThis.$fetch` is undefined under Nitro SSR — use Nuxt's auto-imported `$fetch` identifier (typeof-guarded, globalThis fallback for plain vitest where it's stubbed). Local end-to-end verification of a logged-in app needs THREE dev-only gates (all stage=development AND NUXT_DEV_* env gated): auth store identity injection (Nuxt runtime-config auto-parses JSON env values into objects — typeof-check, don't JSON.parse blindly), navigateToSupplierLogin 401-bypass (business APIs 401 constantly without a real session), and a ?status= mock in the BFF route. Specs touching those modules need `vi.stubGlobal('useRuntimeConfig', () => ({public:{stage:'production'}}))` so the dev branches stay inactive in tests.
- (CTOOL-679 design-align) Banner/placement elements must live INSIDE the content container (`max-w-[1440px] mx-auto px-3 lg:px-4` in base.vue/supplier.vue) — mounting between header and content div makes them full-bleed while the design keeps page bg (bg-navy-5) outside. Measure alignment with getBoundingClientRect in the browser (evaluate_script) instead of eyeballing scaled screenshots — the screenshot scale factor made correct alignment look broken. Reminder: preset `px-4` = 32px (8px scale), NOT 16px.
- (CTOOL-679 gateway round, 2026-09-14) Don't create an app-level Nitro proxy when the upstream endpoint already sits behind an existing same-origin gateway path (here `/api/membership-management` — nitro.devProxy/vite proxy already forward /api to staging); the CTOOL-637 BFF pattern above is for genuinely new upstream hosts. Client-side gates cannot read private runtimeConfig keys (server-only) — dev switches needed on the client must go under `runtimeConfig.public`, wired explicitly via `process.env.NUXT_*` to keep the env name. Factories invoked during layout setup (SSR) must not touch `window` at the top level (e.g. `location.search`) — read it lazily inside the returned functions. The dev-mock triple now lives client-side: identity injection reads `config.public.devUserProfile`, the 401 bypass works client-side too, and `?status=`/`?fail=1` mocking sits inside the api factory (specs stub `{public:{stage:'production', devUserProfile:''}}`).
