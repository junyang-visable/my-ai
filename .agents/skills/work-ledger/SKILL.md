# Work Ledger（个人工作台账）

## Overview

维护个人工作收集账本：所有工作项集中一个文件、固定两节（`## 进行中` 在上、`## 已完成` 在下），已完成条目必须带完成时间。目的：随时快速回顾、向老板汇报有据可查。工作项不限于 Jira 票——需求、专项、故障处理、调研均可登记；Jira 票号只是可选属性。

## 账本文件

路径：`~/Documents/Obsidian Vault/40-Areas/Work Ledger.md`（vault 为 git 仓，误改可从历史找回）。

首次使用且文件不存在时，创建骨架并同时在 `40-Areas/Areas Index.md` 的"领域"列表登记 `[[Work Ledger]]`：

```markdown
---
title: Work Ledger
type: dashboard
tags:
  - dashboard
created: <今天 YYYY-MM-DD>
updated: <今天 YYYY-MM-DD>
---

# Work Ledger

个人工作账本，由 work-ledger 技能维护。时间线只追加，永不删改历史。

## 进行中

## 已完成
```

每次写入后同步更新 frontmatter 的 `updated` 字段。

## 条目格式

```markdown
### <标题>（可含票号，如 CTOOL-719 request_platform 埋点）
- **状态**: <自由文字：评审完成/待排期/开发中/提测/已上线/阻塞/搁置…>
- **登记**: YYYY-MM-DD
- **完成**: YYYY-MM-DD
- **时间线**:
  - YYYY-MM-DD 评审: <范围/关键结论一句话>
  - YYYY-MM-DD 提测: PR #xxx
```

- **完成** 行仅已完成条目有。
- 两节内条目均最新在上：进行中按最近时间线活动排序，已完成按完成日期排序。
- 时间线一行一事件，格式 `YYYY-MM-DD <事件>: <一句话>`；事件名自定（评审/开发/提测/上线/阻塞/恢复/改期/复盘…）。
- 写作口径：写"做了什么+结果"，不写实现细节、不写 Jira 状态标注；评审事件记要点（范围、关键结论、明确不做项）。

## 操作

用户显式说出即执行，不追问二次确认。

1. **登记**「记录/登记工作项 X」：在进行中顶部新建条目。"今天/昨天"换算为绝对日期。
2. **评审**「今天评审了 X / X 评审完成」：账本无此条目→新建（时间线首条=评审要点）；已有→追加时间线并更新状态。
3. **状态变更**「X 提测/上线/阻塞了」：追加时间线一行并更新 **状态** 值。
4. **完成**「X 完成了」：整块（标题+属性行+完整时间线）搬到已完成顶部，补 **完成** 行，从进行中删除。
5. **回顾**「回顾一下我的工作」：Read 账本，对话内紧凑呈现——进行中：标题+状态+最近一条时间线；已完成：标题+完成时间。用户给了时间窗口（如"最近两周"）则据此过滤已完成。

匹配纪律：按标题/票号在账本内查找目标条目；匹配不到或多条命中时，列出候选请用户指认，不猜。

## 编辑纪律

- 每次编辑前 Read 账本全文（用户可能在回合间手工改过），再用 Edit 精确锚点操作；禁止 shell sed/mv/重定向写文件。
- 日期一律绝对格式 YYYY-MM-DD。
- 时间线 append-only：只增不改不删；需要修订时新增一行，不重写旧行。
- 已完成条目同样 append-only：后续动态仍可在其时间线续记（如上线后补复盘），但条目不搬回进行中；确需重开则新建条目并在首行注明"重开自 <原标题>"。
